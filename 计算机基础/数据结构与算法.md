# 数组与链表
* 数组：连续内存，O(1) 随机访问，O(n) 插入删除。缓存友好（局部性好）。
* 链表：非连续内存，O(1) 插入删除（已知位置），O(n) 随机访问。
  * 单链表：只有 next 指针。
  * 双链表：有 prev 和 next，支持双向遍历，占用更多内存。
  * 循环链表：尾节点指向头节点，适合约瑟夫环等场景。

# 栈与队列
* 栈（LIFO）：函数调用栈、括号匹配、表达式求值、DFS。
* 队列（FIFO）：BFS、生产者消费者、任务调度。
  * 双端队列（Deque）：两端都可进出。
  * 优先队列：堆实现，出队按优先级。

# 哈希表
通过哈希函数将 key 映射到数组下标。  
冲突解决：  
* 链地址法：每个桶存链表（或红黑树），冲突元素挂在链上。Java HashMap 用此方式。
* 开放寻址法：冲突后按探测序列找下一个空位（线性探测、二次探测、双重哈希）。  
负载因子 = 元素数 / 桶数。超过阈值需扩容 rehash。  

# 树
* 二叉搜索树（BST）：左 < 根 < 右，中序遍历有序。最坏退化为链表 O(n)。
* AVL 树：严格平衡（左右子树高度差 <= 1），插入/删除需旋转维护平衡。查询多时用。
* 红黑树：弱平衡（5 条性质），插入/删除最多 3 次旋转。Java HashMap、TreeMap 用此结构。
  5 条性质：节点红或黑、根黑、叶子（NIL）黑、红节点的子节点必黑、任一节点到叶子
  的所有路径黑节点数相同。
* B 树 / B+ 树：多路搜索树，每个节点存多个 key，降低树高，适合磁盘 I/O。
  B+ 树非叶子节点只存索引，数据全在叶子节点且叶子间有链表连接。MySQL InnoDB 索引用 B+ 树。

# 图
* 存储方式：邻接矩阵（O(V²)，适合稠密图）、邻接表（O(V+E)，适合稀疏图）。
* 遍历：DFS（深度优先，栈/递归）、BFS（广度优先，队列）。
* 最短路径：Dijkstra（无负权，O(V²)）、Bellman-Ford（有负权）、Floyd（多源最短路径，O(V³)）。
* 最小生成树：Prim（从顶点扩展）、Kruskal（按边权排序 + 并查集）。
* 拓扑排序：DAG 中按依赖关系排序，BFS（Kahn 算法）或 DFS。

# 排序算法
| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
|:---|:---|:---|:---|:---|
| 冒泡排序 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择排序 | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入排序 | O(n²) | O(n²) | O(1) | 稳定 |
| 快速排序 | O(nlogn) | O(n²) | O(logn) | 不稳定 |
| 归并排序 | O(nlogn) | O(nlogn) | O(n) | 稳定 |
| 堆排序 | O(nlogn) | O(nlogn) | O(1) | 不稳定 |

* 快排：选 pivot，小于的放左，大于的放右，递归。不稳定，但平均最快。最坏 O(n²) 在
  pivot 选择不当时（如已有序数组选第一个元素），可用三数取中或随机化优化。
* 归并：分治，合并两个有序序列。稳定，需要额外 O(n) 空间。适合外部排序和链表排序。
* 堆排：建大顶堆，交换堆顶和末尾，堆化。原地排序但不稳定。

# 查找算法
* 二分查找：有序数组，O(logn)。注意边界条件和 mid 溢出（用 mid = left + (right - left) / 2）。
* 哈希查找：O(1) 平均，需要哈希表支持。
* 二叉搜索树查找：O(logn) 平均，O(n) 最坏（退化为链表）。
