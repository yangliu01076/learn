# 异步+最终一致性
针对下单这种业务，我们希望的是最终一致性，而不是强一致性。可以用
自旋消息来实现最终一致性。同时也可以手动推送消息，来实现最终一致性。  
就是说，当前一段业务是用异步消息实现的，当业务完成后，结合幂等性，再发一个本消息
来实现最终一致性。  
同时也给手动推送消息，留下了操作空间。  

# 幂等性
幂等性是指，多次调用同一个接口，结果都是一样的。  
幂等性分为两种，一种是接口的幂等性，一种是数据库的幂等性。  

**注意三方接口的幂等性**

# 缓存设计
对于不变的且频繁查询的数据，可以考虑缓存，比如商品信息，用户信息等。  

# 快速失败
* 当前代码逻辑可以确定走不到后续的时候，可以考虑快速失败，拦截掉。
比如说，查询数据库的时候条件为空，可以考虑快速失败。创建出库单的时候，货品数量为0
的时候，可以考虑快速失败。  
* 也需要考虑分支的快速失败，比如为某些数据新增一些额外的数据的时候，可以考虑当
不满足某些条件的时候，快速失败，即不给这些数据增添额外的数据，**以免做额外的查询操作**
因为补数据肯定得查询相关数据的。
