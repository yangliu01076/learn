责任链模式

# 整体架构
三个核心组件：  
* Sentinel Core：核心库，负责限流、熔断、系统保护等核心逻辑，运行在应用内。
* Dashboard：可视化控制台，负责规则推送、实时监控展示。
* DataSource：数据源，负责规则持久化（Nacos / Apollo / Zookeeper / 文件）。  

# Slot 责任链
Sentinel 的核心设计是 ProcessorSlotChain（责任链），每个资源调用都会经过一系列 Slot
处理。Slot 之间通过 SPI 机制可扩展。  

执行顺序（部分关键 Slot）：  
* NodeSelectorSlot：构建资源调用树，为每个资源创建 DefaultNode（统计节点）。
* ClusterBuilderSlot：构建集群节点 ClusterNode，用于全局统计。
* StatisticSlot：实时统计数据（QPS、RT、线程数），底层用滑动窗口（LeapArray）。
* FlowSlot：流控规则检查，根据 QPS 或线程数判断是否放行。
* DegradeSlot：熔断降级检查，根据慢调用比例、异常比例、异常数判断是否熔断。
* SystemSlot：系统级保护（CPU 使用率、总 QPS、总线程数、入口 QPS、平均 RT）。
* AuthoritySlot：黑白名单授权检查。  

# 流控规则
## 阈值类型
* QPS：每秒请求数。
* 并发线程数：当前正在执行的线程数，能更好地应对突发慢调用。  

## 流控效果
* 直接拒绝：超过阈值直接抛出 FlowException。
* Warm Up（预热）：冷启动时只放行少量请求，经过预热时长后逐渐达到阈值。
  底层基于令牌桶 + 冷启动因子（默认 coldFactor=3，初始阈值 = maxThreshold / 3）。
  适合秒杀等需要预热的场景。
* 排队等待：匀速通过，请求在虚拟队列中等待，超过最大等待时间则拒绝。
  底层基于漏桶思想，严格控制请求间隔。适合突发流量削峰。  

## 流控模式
* 直接：自己达到阈值限流自己。
* 关联：关联资源达到阈值时限流自己（如写达到阈值时限流读，保护写）。
* 链路：只限制从指定入口来的请求。  

# 熔断降级
## 熔断策略
* 慢调用比例：RT > 阈值的请求比例超过设定值，触发熔断。需要设置最大 RT、比例阈值、
  最小请求数、统计时长。
* 异常比例：异常请求比例超过设定值，触发熔断。
* 异常数：异常请求次数超过设定值，触发熔断。  

## 熔断状态机
* CLOSED（关闭）：正常放行，统计指标。
* OPEN（熔断）：拒绝所有请求，等待熔断时长（timeWindow）结束。
* HALF_OPEN（半开）：熔断时长结束后放行一个请求探测，成功则恢复 CLOSED，
  失败则继续 OPEN。  

# 滑动窗口统计
Sentinel 的实时统计基于 LeapArray（滑动窗口），不是简单的固定窗口计数。  
将一个统计周期（如 1 秒）划分为多个格子（如 2 个，每个 500ms），每个格子独立计数。  
窗口滑动时，总统计 = 当前所有有效格子之和。格子越多，统计越平滑，临界问题越小。
